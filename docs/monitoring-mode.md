# Режим мониторинга (большой экран)

Дашборд работает в двух режимах: **обычном рабочем** (как сейчас, для дежурного координатора за десктопом) и **мониторинга** — сводка для большого экрана в комнате координаторов. Режим — это представление одних и тех же данных, а не отдельное приложение: источник, группы и правила классификации не меняются (см. [`incident-classification.md`](incident-classification.md)).

Задача в Jira: [KAN-62](https://sokolenkonikita12ru.atlassian.net/browse/KAN-62), исполнитель — Даниил Поярков.

## 1. Зачем

Большой экран отвечает на один вопрос: **что происходит с массовыми инцидентами прямо сейчас?** Экран смотрит вся смена, включая тех, кто не сидит за дашбордом. Поэтому минимум текста и максимум состояния: крупные счётчики, динамика и цвет. Читается с 3–5 метров за пару секунд.

## 2. Переключение

- Заметная кнопка **«Монитор»** в TopBar (рядом с ручным обновлением, иконка монитора).
- Вход — один клик: разворот на весь viewport (Fullscreen API), LeftRail и служебные панели скрываются.
- Выход — `Esc` или та же кнопка. Обычный режим не меняется.
- `?mode=monitor` в query string — для deep link и автозапуска на стенде у большого экрана.

Кнопка доступна всегда, состояние режима не влияет на рабочие данные: переключение ничего не сбрасывает и ничего не блокирует.

## 3. Что показывает

Сводка только с самым важным. Четыре категории — те же, что на дашборде, с правилами из [`incident-classification.md`](incident-classification.md):

| Категория | Правило | На экране |
| --- | --- | --- |
| Критические | Активный инцидент с `priorityId = 4` | Крупный счётчик, красный акцент |
| Высокий приоритет | Активный инцидент с `priorityId = 3` | Крупный счётчик |
| На координаторах | Активный инцидент или исследование, назначенное на «КЦ ИТ Координаторы Массовых Инцидентов» | Крупный счётчик |
| Исследование ситуации | `stateEnum = Research` | Крупный счётчик |

Сверху — общее количество активных инцидентов и время последнего обновления с индикатором свежести (`live / polling / offline`). Один инцидент может попадать в несколько категорий — это нормально, счётчики считаем независимо.

## 4. Поведение в режиме

- **Алерты не приходят:** полноэкранный overlay критического события и очередь подтверждений («Увидел») не показываются, звук не включается.
- **Ничего не блокируется:** нет модальных окон, подтверждений и действий над инцидентами. Режим полностью read-only.
- Данные обновляются тем же опросом снимка (5 секунд). Экран может висеть часами: следим за переподключением и восстанавливаем опрос после потери сети.
- Скрытие курсора при бездействии — экран «живой», курсор не мешает.

## 5. Графики

Библиотека — **Chart.js** (совместимо со стеком Gravity UI). Цвета и сетка — только через токены темы `--g-*`, никаких захардкоженных hex, чтобы графики корректно работали в тёмной теме.

| График | Тип | Что показывает |
| --- | --- | --- |
| Динамика по категориям | `line`, 4 серии | Открытые инциденты по каждой категории за последние часы — видно рост и пики |
| Распределение по приоритетам | `doughnut` | Доля P1–P4 среди активных инцидентов |
| Нагрузка на координаторов | `bar` | Инциденты «На координаторах» и «Исследование» — очередь смены |

Требования к графикам: без легенд-таблиц, подписи крупные, анимация отключается при `prefers-reduced-motion`, перерисовка не дёргает layout.

## 6. Данные

Счётчики и таймлайн — агрегат, поэтому отдаём их отдельным маршрутом:

```text
GET /api/dashboard/monitoring/summary
```

```ts
interface MonitoringSummary {
  activeTotal: number
  counts: {
    critical: number
    highPriority: number
    coordinators: number
    research: number
  }
  updatedAt: string
  timeline: Array<{
    at: string
    critical: number
    highPriority: number
    coordinators: number
    research: number
  }>
}
```

Таймлайн строит бэкенд из истории инцидентов, чтобы после перезагрузки страницы график не начинался с нуля. Интервал точек — параметр (по умолчанию 5 минут, окно 24 часа).
