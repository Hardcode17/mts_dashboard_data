# Решение: координаторы берут задачи сами, автораспределения нет

Дата: 2026-11-21. Зафиксировал: Artem (по итогам обсуждения).

## Суть решения

Координаторы **сами берут** инциденты из очереди своей группы. Автораспределение (подбор «свободного» координатора системой) **выпадает из решения**.

Полноэкранные критические задачи (P4): когда координатор не в режиме мониторинга / большого дашборда, критический инцидент показывается **на весь экран** и должен быть принят за **60 секунд**. Это окно принятия, а не персональное назначение: система никого не выбирает и никого не переназначает.

## Новая механика взятия (взамен цепочки 31 → 34 → 33)

Создаётся задача **«Координатор сам берёт INC из очереди (claim)»** (эпик KAN-15):

1. **Обычный поток:** координатор видит очередь своей группы (KAN-24) и сам делает claim — команда атомарно закрепляет открытую `coordination_task` за ним; повторный claim тем же координатором идемпотентен; чужая занятая задача не отдаётся. Список «мои задачи» — то, что координатор взял сам.
2. **Критический P4 вне режима мониторинга:** инцидент показывается на весь экран, окно принятия `expiresAt = момент показа + 60 секунд`. Принятие фиксирует `acceptedAt` и оставляет координатора занятым до передачи. Просроченное или чужое принятие отклоняется, INC возвращается просто в очередь — **без автопереназначения и без исключения «пропустившего»**. «Увидел» (ack) не равен принятию.
3. Для остальных приоритетов таймер не заводится.

## Последствия для архитектуры

- Миграция для `coordination_tasks` (сейчас в V7 нет ни исполнителя, ни сроков): нужны `coordinator_id`, `accepted_at` и, для критического окна, `expires_at` — но `expires_at` теперь относится к показу критического события, а не к назначению.
- Фоновый «распределитель»/переназначатель как компонент **не создаётся**.
- KAN-12 (фронт, переназначение вручную) и KAN-58 (изменение инцидентов из дашборда) остаются единственным способом переназначить — руками координатора.
