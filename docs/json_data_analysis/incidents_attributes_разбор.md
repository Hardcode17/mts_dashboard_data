# `incidents_attributes.json` — актуальный справочник атрибутов

## Назначение

Файл описывает **30 полей инцидента**, но не содержит сами инциденты. Каждый элемент массива — объект с тремя ключами:

| Ключ | Смысл | Пример |
|---|---|---|
| `api_source` | Имя поля в записи инцидента | `priorityId` |
| `description` | Человеко-читаемое описание | `Приоритет инцидента` |
| `possible_values` | Пример или перечисление допустимых значений; может быть пустой строкой | `1, 2, 3, 4` |

**Важно:** это справочник для понимания данных, а не строгая JSON Schema. В выгрузке `character_problems.json` **46 полей**, то есть **16 дополнительных** не представлены в этом словаре. Организаторы разрешили дополнять и частично изменять пример данных при сохранении базовых атрибутов.

## Актуальные значения статусов

Словарь содержит переставленные значения `7`/`10` и не перечисляет `20`. **Для проекта используем актуальную таблицу по выгрузке и разъяснениям экспертов.**

| `stateId` | `stateEnum` (из выгрузки) | `state`               | Смысл                                                                              |
| --------: | ------------------------- | --------------------- | ---------------------------------------------------------------------------------- |
|       `0` | `Assigned`                | Назначен              | Инцидент назначен, ещё требует работы                                              |
|       `2` | `WorkInProgress`          | Выполняется           | Инцидент в работе                                                                  |
|       `7` | `Resolved`                | Завершен              | Проблема устранена; можно вернуть в работу                                         |
|      `10` | `Closed`                  | Закрыт                | Вся работа окончена; нельзя вернуть в работу, при повторе создаётся новый инцидент |
|      `20` | `Research`                | Исследование ситуации | Сбой устранён, продолжается исследование причин                                    |

`completionDate` записывает **момент перехода в `Resolved`**, а не момент окончательного закрытия. Поэтому оно может присутствовать у инцидентов в более позднем состоянии (`Research` или `Closed`).

## Правила использования справочника

- **`solution`:** при `Assigned (0)` и `WorkInProgress (2)` должно быть пустым. В тестовой выгрузке оно заполнено у **24 из 24** таких записей — это **ошибка примера**, её разрешено корректировать.
- **Приоритет:** `priorityId` — самостоятельный атрибут; без специально введённого правила не пересчитываем его из `impactId` и `urgencyId`. Критический приоритет — `4`.
- **Даты:** исходный словарь показывает `YYYY-MM-DD HH:MM:SS`, но в фактической выгрузке используется ISO 8601 в UTC (`Z`), иногда с дробными секундами; `deadline` и `completionDate` допускают `null`.
- **`isNeedUp`:** в исходном примере хранится как `true`/`false`/`null`, а не текстовые «Да»/«Нет».
- **Дополнительные поля:** `sysId`, `stateEnum`, `productId`, `serviceId`, `assignedEmployee` и ещё 11 полей описаны в отдельном файле разбора выгрузки.
- **Обновления:** JSON — исходная мини-выгрузка, с которой начинается работа. Дашборд должен реагировать на изменения значимых полей; импорт/экспорт, БД, API и собственные правила статусов — техническое решение команды.

Подробные типы, все **46 полей**, примеры и характеристики тестовых записей см. в [`character_problems_разбор.md`](./character_problems_разбор.md).
