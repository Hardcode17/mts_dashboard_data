## Критический путь — stage-04 «координаторская логика»

Ядро продукта и главная дыра. По решению о самовзятии цепочка стала короткой:

```
KAN-24 (очередь INC с пустым координатором) ──→ KAN-claim (координатор сам берёт INC)
                                                      │
                                                      ▼
                                    KAN-32 (закрытие внутренней задачи
                                    по подтверждённой передаче в ITSM)

Отдельно, без зависимостей:
KAN-30 (доступность = «кто на смене»), KAN-26 (фильтры и поиск)
KAN-35/36 (оповещения, уже в работе у Никиты) — блокер KAN-34 снят
```

Специфика claim:

- обычный INC — координатор сам берёт из очереди (атомарно, идемпотентно);
- критический P4 вне режима мониторинга — полноэкранная тревога с окном принятия **60 секунд** (`expiresAt = момент показа + 60 с`), без автопереназначения;
- для остальных приоритетов таймера нет.

В БД под это нужна миграция: `coordination_tasks` (V7) не содержит ни исполнителя, ни `accepted_at`/`expires_at`.
