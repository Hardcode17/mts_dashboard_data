# Живой показ критического инцидента на Raspberry Pi

До встречи оператор отправляет снимок с одной карточкой доставки. Во время встречи одно нажатие **Send** добавляет новый критический INC по входу через МТС ID. Коллекция получает машинный токен перед каждой отправкой и проверяет в Spring, что обработка пакета завершилась.

## Подготовленный показ на этом Mac

Откройте [рабочее место](http://localhost:3000/) или [общий экран смены](http://localhost:3000/?mode=monitor). Вход выполняется через локальный Keycloak. Тестовые данные для входа хранятся у оператора в `~/.local/share/mcc-local/keys/login.txt`. Этот экземпляр интерфейса читает Spring на порту `8092`.

Исходный снимок уже применён. Во время встречи дважды нажмите [send-local.command](send-local.command) в Finder. Скрипт запускает второй запрос через установленный Postman CLI, получает свежий локальный токен и выводит номер INC после `SUCCEEDED`. Повторный запуск использует тот же пакет. Для запуска из терминала выполните `./send-local.command` из этой папки.

Окружение подготовленного прогона хранится в `~/.local/share/mcc-local/mentor/local.postman_environment.json`. Скрипт берёт секрет из локальной конфигурации во время запуска. Для работы туннель и подключение к Pi не требуются.

Из терминала в корне репозитория выполните:

```bash
cd docs/mentor-demo
./reset-local.command --check   # Проверить, что начальная копия готова
```

Перед показом выполните `./reset-local.command`. Когда понадобится критический INC, выполните `./send-local.command`. Обе команды рассчитаны на Mac с подготовленным стендом в `~/.local/share/mcc-local`, установленными Postman Desktop и OrbStack.

### Что открыть при менторах

1. [Карточка группы на основном стенде](http://localhost:3000/#attention?group=inc%3AINC000021940126). Вверху видны **100 связанных INC** и **11 сервисов**. В основаниях группировки покажите общую зависимость МТС ID и код `AUTH_TIMEOUT`. В составе найдите МТС Premium и KION. У всех ста обращений приоритет P2.
2. [Карточка МТС ID в окне диагностики](http://localhost:5187/?dataset=case#incident/INC000021940126). Нажмите **Открыть разбор ИИ** либо [откройте сохранённый результат](http://localhost:5187/?dataset=case#investigation/INC000021940126?dataset=case&run=2). Раскройте **Основание и исходные записи**. Локальный источник воспроизвёл тайм-аут, агент прочитал запись через MCP, модель Qwen предложила команду профилей. Идентификатор `trace` показывает, какой запрос инженерам проверить дальше. **Повторить разбор** запускает новое наблюдение и модель, для этого на Mac должны работать OrbStack и Ollama.
3. [Очередь «На координаторах»](http://localhost:3000/#overview?section=assigned). Для эпизода с оповещением используйте отдельную подготовленную доставку и команду отправки выше.

### Как начать показ заново

Закончите текущие действия на локальном стенде. Дважды нажмите [reset-local.command](reset-local.command) в Finder и дождитесь **Готово**. Затем обновите вкладки на портах 3000 и 5187. Скрипт вернёт 44 фоновые карточки, доставку P2, группу из 100 INC и исходный разбор ИИ. Критический INC появится при следующем запуске `send-local.command`. Назначения, заметки, подтверждения и последующие запуски ИИ предыдущего прогона останутся в архиве. Персональная раскладка браузера и вход в Keycloak сохраняются.

Из терминала в этой папке команда `./reset-local.command --check` проверяет начальную копию, а `./reset-local.command` выполняет сброс. После успешного сброса скрипт печатает имя архивной базы и путь к прежним файлам. Сброс действует только на менторские службы этого Mac.

## Настройка на ноутбуке оператора

1. В Postman Desktop нажмите **Import** и выберите [коллекцию](mcc.postman_collection.json) и [окружение](pi.postman_environment.json). Выберите окружение **MCC · Raspberry Pi** в правом верхнем углу.
2. В окружении заполните локальное значение **itsm_client_secret** секретом сервисного клиента **itsm-sender** из конфигурации стенда. Оставьте значение локальным. Поле **session_state** при первом запуске должно быть пустым. [Локальные значения в Postman](https://learning.postman.com/docs/use/send-requests/variables/share-variables/)
3. Войдите в сеть стенда и подставьте свой SSH-логин на Pi в команду ниже. Терминал с туннелем должен оставаться открытым во время показа.

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:18081:127.0.0.1:8081 \
  ВАШ_ЛОГИН@raspberrypi.tail029aee.ts.net
```

В другом терминале проверьте доступ к Spring через туннель. Ожидается HTTP 200 с состоянием `UP`.

```bash
curl -fsS http://127.0.0.1:18081/health
```

### Откуда берётся токен

В конфигурации деплоя секрет отправителя задаётся параметром `STAND_ITSM_SENDER_SECRET`. При отдельной настройке `ITSM_MOCK_CLIENT_SECRET` используется действующее значение клиента. Если SSH-учётке оператора разрешён доступ к Docker стенда, на Mac значение можно скопировать в буфер и вставить в локальное поле Postman:

```bash
ssh ВАШ_ЛОГИН@raspberrypi.tail029aee.ts.net \
  'docker exec mts-dashboard-backend-itsm-mock-1 printenv ITSM_MOCK_CLIENT_SECRET' | pbcopy
```

Коллекция вызывает Keycloak по HTTPS с `grant_type=client_credentials` и `client_id=itsm-sender`, затем использует выданный Bearer для отправки и проверки снимка. Токен действует в текущем запросе. Адрес выдачи подтверждается полем `token_endpoint` в [конфигурации Keycloak стенда](https://raspberrypi.tail029aee.ts.net/keycloak/realms/dashboard/.well-known/openid-configuration).

## Два нажатия

| Когда | Запрос в Postman | Что проверить |
|---|---|---|
| До встречи | **01 · Исходный снимок → Send** | В **Test Results** зелёная строка `SUCCEEDED · INC…`. В очереди **На координаторах** по этому номеру открывается карточка «Менторская сессия · курьер не видит заказ» с приоритетом 2. |
| При менторах | **02 · Новый критический INC → Send** | В **Test Results** появится номер второго INC. На [дашборде](https://raspberrypi.tail029aee.ts.net/) найдите «Менторская сессия · массовая ошибка входа» с приоритетом 4. Группа назначения — «КЦ ИТ Координаторы Массовых Инцидентов». Доставка остаётся в очереди **На координаторах** с прежним номером и приоритетом 2. |

Перед вторым нажатием откройте и авторизуйте рабочее место дежурного и общий экран. Держите выбранным то же окружение Postman. Для показа по одному шагу используйте **Send** у нужного запроса. **Run collection** отправит оба снимка подряд.

Ответ `202` означает, что пакет принят. Во вкладке **Test Results** коллекция до 30 секунд ждёт от обработчика `SUCCEEDED`. При обрыве связи или тайм-ауте можно повторить тот же запрос: сохраняются источник, версия, ключ и содержимое. Дубликат INC при этом не создаётся. Если Postman пропустил запрос, причина появится в **Postman Console**. При ошибке Keycloak первым делом проверьте выбранное окружение и локальный секрет.

Для отдельной репетиции очистите **session_state** и снова начните с запроса 01. Будут созданы другой источник и новые номера INC. Предыдущий прогон останется в базе. Пакеты этой коллекции поступают прямо в Spring. Появление INC, очереди и оповещение можно проверять по новому номеру. Для демонстрации записи назначения обратно в стендовую ITSM выберите карточку, известную самой ITSM.
