# Граф связей в карточке инцидента

Внизу карточки инцидента в дашборде, после существующей информации и действий, добавить блок **«Связанные инциденты»**. По нему координатор видит непосредственного родителя и дочерние инциденты и может перейти к их карточкам. Это граф инцидентов, а не граф затронутых сервисов на экране мониторинга.

Jira: [KAN-66 — импорт и API](https://sokolenkonikita12ru.atlassian.net/browse/KAN-66) блокирует [KAN-67 — граф в карточке](https://sokolenkonikita12ru.atlassian.net/browse/KAN-67).

## Данные и бэкенд

- Для иерархии использовать модель [`incident_hierarchies`](database/mts_database_v5_documentation.md#415-строгая-иерархия-инцидентов--incident_hierarchies): у инцидента не больше одного непосредственного родителя, детей может быть несколько. Типизированные связи в `incident_links` (например, дубликаты) не считать родительскими; ручное подтверждение пары уже описано в [KAN-41](https://sokolenkonikita12ru.atlassian.net/browse/KAN-41) и не входит в этот объём.
- В JSON-снимке ITSM добавить необязательное поле `parentId` на дочерней записи. Это строковый номер родителя из поля `id` того же источника (например, `"INC000001"`), не `sysId` и не внутренний ключ БД. Список детей определяется по входящим ссылкам `parentId`, поэтому отдельное поле `childId` не нужно. Исходные файлы заказчика не менять; добавить связи в синтетический стендовый снимок `itsm-mock`. Флаги `isMaster`, `isEffect`, `isReason`, `isDouble` сами по себе не определяют пару инцидентов.
- Импортировать связи после сопоставления инцидентов снимка, независимо от порядка строк. Отсутствие `parentId` не меняет сохранённую связь, `parentId: null` явно снимает связь, импортированную из этого источника. Повторная доставка не создаёт дубли. Неизвестный родитель, ссылка на себя или цикл отклоняют снимок на этапе обработки: предыдущая опубликованная версия остаётся доступной. Узлы без подтверждённых связей не связываются автоматически.
- Добавить **`GET /api/incidents/{id}/relationships`** с тем же допуском, что у карточки. Ответ содержит `focusId`, `nodes` (номер, заголовок, статус и приоритет) и `edges` (`parentId`, `childId`). Граф ограничен одним шагом в обе стороны: выбранный инцидент, непосредственный родитель и непосредственные дети. Для известного инцидента без связей — `200`, один узел и пустой список рёбер; для неизвестного — `404`. Формат задан в [`openapi.yaml`](openapi.yaml).

## Фронтенд

- Загружать граф отдельным запросом для открытой карточки, не блокируя её основные данные. Выделять текущий инцидент, показывать направление «родитель → дочерний» и подписывать узлы номерами и заголовками. Нажатие на соседний узел открывает его карточку и перестраивает граф вокруг него.
- Показать состояния «Загрузка», «Нет связанных инцидентов» и ошибку с кнопкой повторного запроса только внутри блока. Ссылки на связанные карточки должны быть доступны с клавиатуры; текущий узел и направление связи различимы не только по цвету.
- В первой версии граф предназначен для просмотра и навигации. Автоматический поиск связей и редактор рёбер не входят в задачу.

## Сквозная приёмка

Стендовый JSON содержит одного родителя, двух детей и один несвязанный инцидент. В карточке одного из детей внизу видны он и родитель. Переход к родителю показывает обоих детей без дублей. У несвязанного инцидента отображается пустое состояние. Ошибка запроса графа не мешает пользоваться карточкой.
